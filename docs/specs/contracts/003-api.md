# API contract: dashboard (specs 001-003 and 010, consumed by 005-009; updated by instruction 011)

Server: Node + Express, bound to `HOST` (default `127.0.0.1`), port from `PORT` (default `47615`). All endpoints are `GET`, JSON, read-only, except `POST /api/open` (spec 013). Auth: none on loopback; when `DASHBOARD_TOKEN` is set, other machines need the token (spec 014). Any unexpected exception returns HTTP 500 `{ "error": "<short message>" }`.

Environment:

| Variable | Meaning | Default |
|---|---|---|
| `PORT` | server port | `47615` |
| `HOST` | address to listen on; anything but a loopback address requires `DASHBOARD_TOKEN` (spec 014) | `127.0.0.1` |
| `DASHBOARD_TOKEN` | shared token for access from other machines, at least 16 characters (spec 014) | none |
| `EDITOR_COMMAND` | editor CLI used by `POST /api/open`; letters, digits, `.`, `_`, `-` only (spec 013) | `code` |
| `CLAUDE_PROJECTS_DIR` | transcript root scanned by spec 001 | `~/.claude/projects` |
| `GOOGLE_APPLICATION_CREDENTIALS` | path to the service account key file (spec 002) | none (Sheets then report `error`) |

Static files: if `web/dist` exists, the server serves it at `/` (relative to the repo root). The frontend dev server proxies `/api` to `http://127.0.0.1:47615`.

## Shared shapes

```ts
type Status = 'Extracted' | 'Confirmed' | 'Spec Written' | 'Built' | 'Rejected'   // Row.status may also be 'Unknown' (MAP rows)

type Row = {            // one requirement; every field is a string, missing = "". For Sheet rows, status is the effective status (see below)
  id: string; title: string; summary: string; source: string
  priority: string; status: string; spec: string
}

type SessionItem = { sessionId: string; title: string; lastActivity: string }  // ISO 8601, title "" if none

type Requirements = {
  status: 'ok' | 'no-sheet' | 'error'
  source: 'sheet' | 'map' | 'none'   // where the rows came from; 'none' when status is not 'ok'
  counts: { Extracted: number; Confirmed: number; 'Spec Written': number; Built: number; Rejected: number }  // all 0 unless status is 'ok'
  rows: Row[]           // [] unless status is 'ok'
  sheetUrl?: string     // https://docs.google.com/spreadsheets/... only; present when the Sheet URL is valid (also when status is 'error'); absent for source 'map' / no Sheet
  error?: string        // short text, only when status is 'error'; never contains key material
}
```

## GET /api/projects

Response 200:

```json
{
  "activeMinutes": 5,
  "canOpen": true,
  "kpis": { "activeProjects": 3, "sessionsToday": 14, "openRequirements": 9, "built": 12, "totalRequirements": 30 },
  "projects": [
    {
      "name": "nin-claude-dashboard",
      "path": "f:/naim/nin-claude-dashboard",
      "sessions": 8,
      "lastActivity": "2026-10-05T10:20:00.000Z",
      "active": true,
      "sessionList": [ { "sessionId": "…", "title": "…", "lastActivity": "…" } ],
      "requirements": { "status": "ok", "source": "sheet", "counts": { "Extracted": 0, "Confirmed": 3, "Spec Written": 1, "Built": 4, "Rejected": 0 }, "rows": [] }
    }
  ]
}
```

- `canOpen` is true when the request comes from the same machine (loopback peer), false otherwise (spec 013).
- `name` is the last segment of `path`. `sessions` equals `sessionList.length`.
- Sorted: `active` first, then `lastActivity` descending.
- `kpis.openRequirements` = sum of `Extracted` + `Confirmed` + `Spec Written` across projects. `kpis.built` = sum of `Built`; `kpis.totalRequirements` = sum of all counts except `Rejected`. `kpis.sessionsToday` = sessions whose `lastActivity` is on the same local day as now.

## GET /api/feed

Query: `project` (optional, matches `name` exactly). Response 200: `FeedItem[]`

```json
[ { "project": "nin-claude-dashboard", "sessionId": "…", "title": "…", "lastActivity": "…" } ]
```

Newest first by `lastActivity`, at most 100. An unknown `project` returns `[]` (not an error).

## GET /api/pipeline

Query: `project` (optional). Response 200:

```json
{ "Extracted": [], "Confirmed": [], "Spec Written": [], "Built": [], "Rejected": [] }
```

Each array holds `Row & { "project": string }`, in project order then Sheet order. Only projects whose `requirements.source` is `sheet` appear. A row whose `status` is not one of the five is left out. An unknown `project` returns five empty arrays.

## GET /api/insights (spec 015)

Query: `project` (a name from `/api/projects`, required), `days` (optional; `7` or `30`, anything else means all time). Response 200:

```json
{
  "status": "ok",
  "days": null,
  "totals": { "responses": 209, "outputTokens": 199590 },
  "models":  [ { "model": "claude-sonnet-5-5", "responses": 209, "percent": 100, "outputTokens": 199590 } ],
  "plugins": [ { "plugin": "nin-plugin", "responses": 34, "percent": 16.3 }, { "plugin": null, "responses": 175, "percent": 83.7 } ],
  "skills":  [ { "skill": "nin-plugin:prd-to-requirements", "plugin": "nin-plugin", "responses": 6, "percent": 2.9 } ]
}
```

- A response is one `message.id` (not a transcript line). `percent` is `responses / totals.responses * 100` with one decimal (0 when there are no responses). `plugin: null` means "no plugin".
- `models` and `plugins` are sorted by `responses` descending; `skills` holds at most 10 rows.
- An unknown `project` or a project without transcripts returns 200 with `status: "none"`, `totals` of 0 and empty lists. A path is never accepted. Only names and counts are returned, never message text.

## POST /api/open (spec 013)

Opens a project folder in the editor on the server machine. Request: `Content-Type: application/json`, body `{ "project": "<name>" }` (a path is never accepted).

- 200 `{ "ok": true }`
- 403 `{ "ok": false, "error": "…" }`: the peer is not the same machine, or an `Origin` header is present and is not `http://127.0.0.1:<port>` / `http://localhost:<port>`.
- 415: content type is not JSON. 404: no project with that name. 429: the same project was opened less than 2 seconds ago.
- 500 `{ "ok": false, "error": "…" }`: the folder is missing or invalid, or the editor command was not found.

## Notes

- Sheet failures never change the HTTP status: they appear as `requirements.status = 'error' | 'no-sheet'` on that project only.
- The server never writes to `~/.claude` or to any Sheet.

## Requirement sources (instruction 011, spec 010)

- **Sheet ok** (`source: "sheet"`): rows are the Sheet rows. A row whose `spec` value is a MAP id pointing at a spec file with `status: built` is reported with `status: "Built"`, even if the Sheet still says `Spec Written`. Other rows keep their Sheet status. `counts` are tallied on these effective statuses.
- **Sheet error**: `status: "error"`, `source: "none"`. The MAP fallback is not used, so the failure stays visible.
- **No Sheet, MAP with specs** (`source: "map"`, `status: "ok"`): one row per spec, `{ id, title, summary: "", source: "MAP", priority: "", status, spec: id }` with `status` `Built` (spec `built`), `Spec Written` (spec `draft`) or `Unknown`. `counts` tally only `Built` and `Spec Written`.
- **Neither**: `status: "no-sheet"`, `source: "none"`.
